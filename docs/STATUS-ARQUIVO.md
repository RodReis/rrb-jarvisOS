## 2026-08-31 — Reconciliação do PR #189 e histórico transferido do STATUS

O STATUS passou a retrato curto conferido no board; #103 é o next nesta consulta. As notas abaixo são históricas, preservadas da main consultada (2e8151f), não instruções de fila nem evidência de entregas deste PR. Fatos atuais prevalecem sobre os snapshots antigos.

> **M8-F06 entregue (2026-08-30) — o MVP-008 fecha.** Roadmap, DAG e gates por revisão. **A decisão que define a fatia é a separação entre gerar e aprovar**: se gerar promovesse o MVP para a fila, a geração estaria aprovando o que ela mesma propôs (critério 3); se aprovar aceitasse autor qualquer, a delegação aprovaria gate (critério 7). > **M6-F04 entregue (2026-08-29).** As nove capacidades idempotentes do GitHub: repositório, issue, sub-issue, ref, PR, checks, actions, squash merge e merge state. **Todo `ensure*` procura antes de criar** — a única forma de "repetir não duplica" valer contra uma API sem upsert —, e a idempotência de issue vem de uma **chave externa no corpo**, não do título: título muda quando alguém reescreve, e a issue nasceria de novo a cada mudança. **1189 testes** (+74) e **8 E2E** no app real. **Dois pontos que a API cobra:** o `sha` no merge é o que faz o GitHub barrar head divergente com 409 (a garantia vem do serviço, não de uma comparação nossa que poderia estar velha), e o `merge_commit_sha` de PR **aberto** é um *test merge commit* que não está em branch nenhum — descartado, nunca repassado como merge real. **O E2E achou um defeito da F03 em produção:** o `validar` do adapter checava credencial, mas o `ConnectorService` o chama **antes** de resolver o cofre — então a guarda recusaria toda chamada ao GitHub; só tinha teste unitário, onde o secret é passado à mão. **E um contrafactual mostrou que o dublê mentia:** sem o `sha` no merge, o teste do head divergente passava, porque o fake recusava `undefined` enquanto a API real mergeia — corrigido o fake, o contrafactual reprova o teste certo. **Verificado no app real** com servidor que conta requisições: repetir `ensure` faz um POST só, e `verifyAuditChain` → `ok`. **O smoke real (17/17, repositório descartável autorizado pelo PI) achou o que nenhum fake acharia:** a listagem de issues do GitHub é eventualmente consistente — leva ~4 s para mostrar o que acabou de ser criado, e dois `ensureIssue` seguidos duplicariam a issue.
